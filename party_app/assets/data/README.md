# 지하철역 좌표 데이터 (`subway_stations.json`)

상세 화면 주소 아래의 `②⑧ 잠실역 · 770m` 한 줄이 쓰는 데이터다.
앱은 **이 파일 하나만** 읽는다([`lib/services/subway_station_index.dart`](../../lib/services/subway_station_index.dart)).
지금은 빈 파일이라 지하철 행이 표시되지 않는다 — 아래 절차로 채우면 바로 나온다.

## 왜 API가 아니라 번들 데이터인가

이 프로젝트가 쓰는 네이버 자산으로는 "이 좌표에서 가장 가까운 역"을 물을 수 없다.

- `flutter_naver_map` SDK — 지도 렌더링 전용. 장소·POI 검색 API 없음
- NCP Maps **Geocoding**(`geocodeAddress` Cloud Function) — 주소 → 좌표 변환만
- `openapi.naver.com/v1/nid/me` — 로그인 프로필 조회

좌표만 있으면 답이 나오는 질문이라, 새 API를 붙이는 대신 역 좌표를 번들해 앱
안에서 계산한다(호출 비용·지연·쿼터가 모두 없다).

## 1. 받아야 할 원본 데이터

**역 중심 좌표**만 있으면 된다(출구별 좌표는 필요 없다).

| 항목 | 내용 |
|---|---|
| 후보 1 | 공공데이터포털(data.go.kr) — **전국 도시철도역 정보**(역명·노선·위경도) |
| 후보 2 | 서울열린데이터광장(data.seoul.go.kr) — 서울교통공사 **역사 좌표** |
| 후보 3 | 각 지역 교통공사(부산·대구·인천·광주·대전) 역사 좌표 |
| 형식 | CSV(UTF-8 권장) |

### 필요한 컬럼 (이름은 데이터셋마다 다르므로 대응만 되면 된다)

| 필요한 값 | 흔한 컬럼명 | 필수 |
|---|---|---|
| 역명 | `역명`, `역사명`, `전철역명`, `station_name` | **필수** |
| 호선 | `호선`, `노선명`, `전철노선명`, `line` | **필수** |
| 위도 | `위도`, `lat`, `YCODE` | **필수** |
| 경도 | `경도`, `lng`, `XCODE` | **필수** |
| 역 코드 | `역번호`, `역코드`, `station_cd` | 선택 |

> 좌표계 주의: 값이 위경도(37.x / 127.x)가 아니라 TM/UTM-K(수십만 단위)인
> 데이터셋이 있다. 그런 파일은 **WGS84 위경도로 변환된 버전**을 받아야 한다.
> 변환기는 위경도 범위를 벗어난 행을 버리고 건너뛴 개수를 알려준다.

환승역이 노선 수만큼 여러 행으로 들어 있어도 된다 — 변환기가 역 하나로 합치고
노선을 모아 준다.

## 2. 변환

원본 CSV는 `party_app/tool/data/`에 둔다(앱 번들에 들어가지 않는 개발용 입력이다).
`assets/data/`에는 최종 `subway_stations.json`만 남긴다.

### 인코딩

공공데이터 CSV는 **EUC-KR인 경우가 많다.** 변환기는 UTF-8만 제대로 읽으므로 먼저
바꾼다(PowerShell).

```powershell
$src = "tool\data\원본.csv"; $dst = "tool\data\원본_utf8.csv"
$t = [IO.File]::ReadAllText($src, [Text.Encoding]::GetEncoding(51949))
[IO.File]::WriteAllText($dst, $t, (New-Object Text.UTF8Encoding($false)))
```

### 실행

```bash
cd party_app
dart run tool/subway_data_builder.dart --in tool/data/seoul_utf8.csv --city 서울
```

여러 파일을 합칠 때는 `--in`/`--city`를 반복한다. 역명이 같으면 **한 역으로 합치고
노선을 모은다**(강남역에 2호선 + 신분당선이 붙는 식).

```bash
dart run tool/subway_data_builder.dart \
  --in tool/data/seoul_utf8.csv --city 서울 \
  --in tool/data/korail_utf8.csv --city 수도권
```

컬럼 자동 인식이 실패하면 이름을 직접 지정한다.

```bash
dart run tool/subway_data_builder.dart --in x.csv \
  --col-station 역사명 --col-line 노선명 --col-lat 위도 --col-lng 경도 \
  --col-code "고유역번호(외부역코드)"
```

### 좌표가 파일마다 다를 때

- **한 파일 안**에서 같은 역이 여러 행이면 노선별 승강장이다 → 평균을 내
  역사 한가운데를 가리킨다(잠실역 2호선·8호선은 400m쯤 떨어져 있다).
- **파일 사이**에 300m 넘게 어긋나면 한쪽이 틀린 것이다 → 평균 대신 **먼저 넣은
  `--in` 파일 값을 채택**하고 목록으로 알린다.

그러므로 **더 믿을 만한 파일을 앞에 넣는다.** 경고 목록을 보고 어느 쪽이 맞는지
판단한 뒤 순서를 바꾸거나 원본을 고치면 된다.

## 3. 검증

```bash
dart run tool/subway_data_check.dart --focus 잠실 --focus 강남 --focus 홍대입구
```

역/노선 수, 파일 크기, 로드 시 메모리 증가량, 중복(역명·좌표), 환승역 병합 결과,
노선 누락, 200m 안에 붙어 있는 다른 이름의 역(같은 역 중복 의심)을 보고한다.
`--probe "이름,위도,경도"`로 임의 좌표의 최근접 역을 출력해 지도와 대조할 수 있다.

## 4. 결과 형식 (앱이 읽는 형식)

```jsonc
{
  "version": 2,
  "generatedAt": "2026-08-09",
  "source": "공공데이터포털 전국 도시철도역 정보",
  "stations": [
    {
      "name": "잠실",              // '역'은 붙이지 않는다(앱이 붙인다)
      "lines": ["2호선", "8호선"],  // 환승역이면 여러 개
      "code": "216",              // 선택
      "city": "서울",              // 선택(같은 역명 구분용, 예: 시청역)
      "lat": 37.513413,
      "lng": 127.100132
    }
  ]
}
```

- 환승역은 노선마다 승강장 좌표가 조금씩 달라 **평균**을 쓴다(수십 m 차이는
  "가장 가까운 역" 판정에 영향이 없다).
- 노선 **색은 이 파일에 넣지 않는다** — 코드 상수
  [`SubwayLineStyle`](../../lib/models/subway_line_style.dart)에서 관리한다.
- 호선 값이 `1`, `02`처럼 숫자만 있는 데이터는 `1호선` 형태로 바꿔 저장한다
  (그대로 두면 노선 색을 못 찾고 배지도 "1"로 읽힌다).

## 현재 반영된 데이터

| 항목 | 값 |
|---|---|
| 원본 | 서울교통공사 역사 좌표 (`tool/data/seoul_subway_stations.csv`, EUC-KR) |
| 범위 | **서울 1~8호선만** — 239역 |
| 빠진 것 | 9호선·신분당선·공항철도·경의중앙선·수인분당선·우이신설선·신림선, 서울 밖 전 지역 |

원본 데이터에 **좌표 오류 2건**이 확인됐다(공사 데이터 자체의 오류다).

| 역 | 문제 |
|---|---|
| 마곡 / 발산 | 두 역의 좌표가 완전히 동일 |
| 잠실나루 / 잠실새내 | 10m 차이(실제로는 잠실역을 사이에 둔 반대편) |

추정으로 고치지 않았다. 신뢰할 수 있는 다른 데이터셋을 `--in`에 함께 넣으면
변환기가 차이를 알려주므로, 그 파일을 앞에 두어 교정하면 된다.

## 5. 앱 동작

- 장소 좌표에서 가장 가까운 역 **하나**를 찾아 노선 배지 + 역명 + 거리를 보여준다.
- **1.5km를 넘으면** 행 자체를 숨긴다(`SubwayStationIndex.defaultMaxMeters`).
- 데이터에 없는 지역이면 결과가 없을 뿐, 오류는 나지 않는다.
